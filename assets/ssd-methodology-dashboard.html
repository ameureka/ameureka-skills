Specification-State-Distill (SSD) 模式开发教学图

适合 AI 时代独立黑客（Indie Hacker）与协同开发团队的高合规、低漏洞工程闭环

01

Specification (规范定义与对抗审计)

核心目标：消除开发盲区，物理化契约
步骤 1.1

模糊需求输入

录入原始商业想法或开发需求，由于存在不确定性，此时往往存在大量开发盲区（Unknowns）。

步骤 1.2

8维盲区审计

通过 `blindspot-audit` 针对 ACC(准确性)、COV(覆盖率)、USE(可用性) 等 8 个维度展开全方位对抗审查。

步骤 1.3

象限对抗与证伪

对发掘的盲区进行校验，过滤假阳性噪点，决策分类后写入总账单，输出物理 specs 契约与行动 Plan。

👇
02

State (状态验证与双跑测试门禁)

核心目标：确保状态正确，物理防异变
步骤 2.1

AI 自动开发 Loop

AI 助手载入 Spec 契约和 Plan 任务清单，在受控的 workspace 中进行代码编写并循环运行。

步骤 2.2

真实集成双跑

拒绝 mock。对敏感数据和复杂交易，接入本地 PostgreSQL 真实数据库执行双跑校验，保障状态前后守恒。

判定与拦截 (Mutation Gate)

变异门禁守卫

检测到不符合 Specs 契约的越权或错误状态修改？
❌ 是：拒绝并阻断，自动返回步骤 2.1 重跑。
✅ 否：通过门禁，达成契约（Goal Achieved）。

👇
03

Distill (踩坑教训蒸馏与反哺)

核心目标：沉淀团队记忆，完成系统迭代
步骤 3.1

收集拦截日志

收集在 State 验证阶段被门禁拦截的现场、安全防护（Safeguards）报错、以及环境污染的详细数据。

步骤 3.2

本质教训蒸馏

剥离表面报错噪声，提炼出具有普适性的经验规则，比如“如何设计防范 API 降级的探测机制”。

步骤 3.3

回填知识库 (References)

将教训写入本地 references 引用库或 AI 本地的记忆（claudemem），更新 CLAUDE.md 中系统协同规则。

🔄 反哺闭环逻辑： 步骤 3.3 的成果将直接回填并融入到下一次的 **01 阶段** 盲区审计维度库中，保证团队在面对新迭代时永不踩同一个坑。
