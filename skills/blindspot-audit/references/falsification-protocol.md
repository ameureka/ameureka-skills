# 对抗证伪协议 + 误报防御清单

> 用途：Step 5。全部 P0/P1 发现在进入 00 总览前必须走本协议。
> 实战校准：009 一轮 19 条 P0/P1 → 17 CONFIRMED / 2 DOWNGRADED / 0 REFUTED；
> 007 一轮 6 条 P0 → 2 条被证伪+用户确认拉下（均为「用户独有知识」类误报）。
> 证伪波的成本 ≪ 按误报立项实施的浪费。

## 证伪者提示词模板

```
你是独立证伪者。你的任务是对下列发现尝试【反驳】，而不是复述确认。

发现：{ID} {标题}
原审计者的证据：{file:line 列表 + 论证摘要}

纪律：
1. 不信任原审计者的任何引用——你自己重新读代码，独立重推每个 file:line
   （文件可能已变化，锚点可能漂移；漂移本身要报告）
2. 双向找证据：既找支持该发现的证据，也找反驳它的证据，两边都要写
3. 三个高频翻车点逐一排查：
   a. 设计 vs 实现混淆——文档/注释描述的机制真的在 runtime 存在吗？
      grep 实际调用点，数出来（历史翻车：把"设计过从未实现"当"已实现有 bug"）
   b. 反向混淆——文档说"未接线"就当真了吗？grep 实际消费点
      （历史翻车：channel_group_pricing 文档说未接线，实际热路径已接）
   c. 语境缺失——这条结论是否依赖只有用户才知道的事实
      （资产归属/内容真实性/历史拍板/环境模式）？是 → 标注"需用户确认"
4. 数量断言逐个重验（"全仓只有 2 处消费点"→ 你自己 grep 数一遍）
5. 环境探测类证据（DNS/网络/第三方状态）视为不可信，标注需在干净环境或由用户复核
6. 审查原审计者实测证据的**有效性**：用"必然失败的输入"测出的失败证明不了机制
   （008 实锤：用假 key 测得 401 被当作"session-only 的双证"——假 key 对任何端点都 401，
   证据无效须剔除；结论可能仍真，但必须换有效证据重新支撑）

裁定（四选一）+ 一段裁定依据（含你独立核过的锚点）：
- CONFIRMED：证据成立，严重度维持
- DOWNGRADED：属实但严重度高估（说明新级别与理由：暴露度低/有兜底/影响面小）
- UPGRADED：属实且比原判更重（说明升级理由）
- REFUTED：不成立（说明反例）
```

## 编排规则

- 分批执行，每批 ≤5 条（批内并行，批间顺序）
- 证伪者与原审计者必须是**不同的 agent 实例**（不共享上下文）
- 交叉实锤加权：同一问题被多个维度独立发现（如 009 的 SW-1 被 CHK/SEC/BLD/ADM 四维实锤）= 内建证伪，可简化为锚点复核
- 裁定表落盘进 00 总览（格式：ID / 维度 / 裁定 / 关键依据锚点）
- REFUTED 的发现不删除——在维度文档原地标注裁定与理由，防止下一轮审计重新发现它

## 限额/资源受限降级协议（008 首跑实锤：审计波跑完限额耗尽，证伪 agent 无法再 spawn）

证伪波撞会话限额时，**不弃守也不硬等**，按以下降级序执行并在裁定表诚实登记方式：

1. **交叉实锤项**（≥2 维独立发现同一问题）→ 视为内建证伪，主线程只做锚点复核，裁定可发 CONFIRMED
2. **单源 P0** → **主线程亲自独立验证**（自己 grep/curl/读码，不信原 agent 的引用；截图类证据用 Read 工具直接读图复核——008 的 LEK-1 即主线程读图裁定）。主线程此时就是证伪者，须遵守本协议全部纪律
3. **单源 P1** → 裁定标 **PENDING**，在 00 总览裁定表显式登记「限额中断，未过独立证伪；实施前必须逐条前提复核（file:line 对当时 HEAD 重验）」；限额重置后可补跑证伪波回填裁定
4. **禁止**：把 PENDING 项静默当 CONFIRMED 写进批次计划；用"审计 agent 说了"替代独立验证

补充经验：审计 agent 撞限"失败"时报告常已落盘（只丢返回值）——先 `ls + wc -l + tail` 盘磁盘再决定重跑（009/008 两轮 100% 救回）。

## 误报防御清单（审计与证伪双方都要过）

| 误报类型 | 实战案例 | 防御 |
|---------|---------|------|
| 环境污染 | 007：本机 dig 被 Clash fake-ip 污染 → 误判"客服邮箱无 MX 是黑洞"（连公共 DNS 查询都被劫持） | 网络/DNS/第三方探测类结论一律标"待干净环境复核"，禁止直接定 P0 |
| 用户独有知识 | 007：误判 token101.ai 是废域（实为用户持有的生产域，替换方向整个反了）；误判证言伪造（实为真实有授权） | 资产归属/内容真实性/历史决策必须走访谈确认门；确认前只能挂"待确认" |
| 设计当实现 | flow5h/7d：文档+mock 齐全但 runtime 从未实现，被当成"已实现有 bug"分析了一轮 | 断言机制存在前先 grep 运行时调用点 |
| 文档当实态（反向） | channel_group_pricing：文档说未接线，实际 billing 热路径已接 | 断言机制不存在前同样先 grep |
| 锚点漂移 | 009 Wave 1 前提复核发现 4 处无害锚点漂移 | 证伪/实施前按当前 HEAD 重验 file:line |
| 已修误报 | 007 基线 MKT-13 已修（discountApplied 自描述），若不逐项复核会重复立项 | 上游基线逐项复核「仍在/已修/部分修/需重定性」 |
| 名义值反推 | activation_hot_199 名义 199 实价 4.0 CNY；PROMO_FIRST_TOPUP_20 名义 20 实为 10% | 禁止从标识符字符串反推业务数值，一律查运行时规则源 |
| 假阴性证据 | 008：用假 key 测 me/* 得 401 被当"session-only 双证"——假 key 对任何端点都 401 | 用"必然失败的输入"测出的失败不能证明机制存在；鉴权类型判定须读鉴权实现代码，或用有效凭证对照测试 |
| 幻觉锚点 | 008：COV agent 引用 auth.ts:177 的 enableSessionForAPIKeys——全仓 grep 0 命中，该锚点不存在（但结论经换证据后仍成立） | 证伪者对每个 file:line 独立重推；锚点不存在 ≠ 结论错误，换有效证据重新裁定 |
