# 10 层技术分类法详解

## 分类原则

按**技术维度**组织需求，而非按优先级或功能模块。每个问题根据其**技术本质**归入对应层级。

## 各层详细定义

### Layer 10: business-logic（前缀 BL）

**职责**: 业务核心逻辑，不涉及具体技术实现细节

**典型内容**:
- 数据聚合逻辑（统计查询、收入计算）
- 状态机（订单状态流转、用户生命周期）
- 业务规则（定价公式、折扣策略、权限矩阵）
- 算法（推荐、排序、匹配）

**判断标准**: 如果去掉技术框架（Next.js → Express），这个逻辑是否仍然存在？是 → BL

**边界案例**:
- "Dashboard 需要显示总收入" → BL（聚合逻辑）而非 UI（展示）
- "计费扣费流程" → BL（业务规则）而非 DB（数据操作）

### Layer 20: api-specs（前缀 API）

**职责**: 接口定义，关注请求/响应格式和端点规范

**典型内容**:
- Server Action 规范（输入 schema、输出格式）
- REST/GraphQL 端点定义
- 请求/响应格式（Zod schema）
- 错误码定义

**判断标准**: 是否定义了"系统边界上的数据交换格式"？是 → API

### Layer 30: database（前缀 DB）

**职责**: 数据模型和查询优化

**典型内容**:
- Schema 变更（新表、新字段）
- 查询优化（N+1 修复、批量查询）
- 索引策略
- 数据迁移

**判断标准**: 是否涉及数据库表结构或查询性能？是 → DB

### Layer 40: frontend（前缀 UI）

**职责**: UI/UX，用户可见的界面和交互

**典型内容**:
- 页面结构（新页面、页面重构）
- 组件规范（新组件、组件清理）
- 交互设计（loading 状态、toast 反馈、动画）
- 响应式布局
- 模板残留清理

**判断标准**: 是否直接影响用户看到的界面或交互体验？是 → UI

### Layer 50: integration（前缀 INT）

**职责**: 外部系统集成

**典型内容**:
- 第三方 API 集成（Stripe、OAuth、邮件服务）
- Webhook 处理
- SDK 配置
- 外部数据同步

**判断标准**: 是否涉及与外部系统的数据交换？是 → INT

### Layer 60: security（前缀 SEC）

**职责**: 安全规范

**典型内容**:
- 权限检查（角色验证、资源访问控制）
- 输入验证（XSS 防护、SQL 注入防护）
- 数据脱敏（敏感信息隐藏）
- 认证/授权流程

**判断标准**: 是否涉及"谁能做什么"或"数据安全"？是 → SEC

### Layer 70: code-standards（前缀 CODE / NAV）

**职责**: 代码规范和项目结构

**典型内容**:
- 命名约定
- 目录结构规范
- i18n 规范
- 导航配置（侧边栏、路由注册）
- 代码风格

**判断标准**: 是否关于"代码怎么写"而非"代码做什么"？是 → CODE
**特殊**: 导航/路由配置使用 NAV 前缀

### Layer 80: observability（前缀 OPS）

**职责**: 可观测性

**典型内容**:
- 日志规范（结构化日志、日志级别）
- 指标采集（性能指标、业务指标）
- 告警配置
- 错误追踪

### Layer 90: testing（前缀 QA）

**职责**: 测试策略

**典型内容**:
- 单元测试策略
- E2E 测试用例
- 视觉回归测试
- 测试覆盖率要求

### Layer 99: deployment（前缀 DEP）

**职责**: 部署和环境

**典型内容**:
- 环境配置（开发/预发/生产）
- CI/CD 流水线
- Docker 配置
- 环境变量管理

## 编号规则

```
目录: {层级编号}-{类别}/
文件: {前缀}-{序号}-{中文标题}.md
序号: 三位数，从 001 开始

示例:
10-business-logic/BL-001-Admin运营数据聚合.md
10-business-logic/BL-002-课程推荐算法.md
40-frontend/UI-001-Dashboard模板残留清理.md
40-frontend/UI-002-Admin运营概览面板.md
```

## 历史变体说明

历史项目存在 `20-api`、`70-code`、`REQ-50-01` 等目录名/编号变体，属遗留漂移，不作规范依据。
新矩阵一律使用正典全名（如 `20-api-specs`、`70-code-standards`）与 `{PREFIX}-{NNN}` 前缀编号（如 `SEC-001`），不得沿用变体。

## 前缀对照表

层级 ↔ 目录 ↔ 前缀的权威对照见 [SKILL.md](../SKILL.md)「10 层技术分类法」主表（单一权威源，此处不再复制副本）。

## 跨层问题处理

一个问题可能涉及多个层级。处理原则：

1. **按技术本质归入主层级**，在交叉引用中标注关联层级
2. 例如："Admin 订单管理页面"
   - 主层级：UI-003（页面结构）
   - 交叉引用：API-001（查询端点）、BL-001（数据聚合）、NAV-001（导航配置）
